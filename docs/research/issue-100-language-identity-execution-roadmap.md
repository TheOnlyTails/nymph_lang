## Frozen corrections and exclusions

The tickets preserve these settled corrections verbatim:

1. **Echo:** complete visibility-independent recursive rendering of ordinary structure, never `Debug`;
   inert placeholders for functions/resources/opaque externals.
2. **Roots:** only the settled normalized root matrix, `E: Display`, inert ordinary build modules, and
   the exact synchronous/task launcher policy: success 0, application `None`/`Error` 1, orderly SIGINT
   130, SIGTERM 143, defect 101.
3. **Enums:** fixed-point deduplicated source-variant sets/static views; cycles/diamonds legal; no
   wrappers/source-spread patterns; embedding generates no `Into`; direct set assignability first and
   unique explicit pure infallible `Into` only as fallback.
4. **Iteration/control:** nominal `Iteration<Item, Next>`, capability-preserving `self`, dedicated
   `For`, immutable header state `loop` with named simultaneous `continue`, and no source `while`.

No ticket introduces a compatibility execution mode, generated enum `Into`, visibility-filtered echo,
an open root-policy decision, an Option iterator ABI, source `while`, a browser runtime, actor language
support, or an alternate backend.

## Integration boundaries

1. **Stable contracts precede syntax.** A source node is complete only when parser/recovery, formatter and
   all walkers, sema, complete/recovered interfaces, `RuntimeAnnotations`, stable lowering, HIR,
   backend/runtime, ordinary diagnostics, and focused tests agree. Lowering never consults Salsa or an
   AST, repeats semantic proofs, or infers behavior from JavaScript names.
2. **R0–R12 are internal and independently green.** They may land in dependency order but must not be
   released as a partial source-language identity. There is no feature-flag language fork or second
   checker/session path.
3. **Iteration/runtime-role migration is explicit.** Ticket #118 atomically replaces the public iterator
   ABI, `For` lowering, stdlib adapters/terminals/ranges/collection roles, and runtime bridge before R13.
4. **Migration evidence precedes deletion.** Ticket #103 freezes the corpus and inventory; #123 proves
   safe edits/manual outcomes; #125 migrates docs/examples/generated producers; #126 proves the whole
   readiness gate. All are native prerequisites of the R14 chain.
5. **R13 directly blocks R14.** Ticket #127 has the single direct native blocker #126. No old source
   acceptance changes before that edge clears.
6. **R14 is one public cutover.** Tickets #127–#130 are an ordered integration line. The recovery switch
   and deletions are reviewable internal changes, but #130 owns the sole public compatibility statement
   and full release-candidate verification. It does not itself publish a release.
7. **Retirement is conditional.** Ticket #131 removes migration-only recognition and clients only after
   the documented support-window/release condition is proven. Old syntax is never reaccepted.

Permanent boundaries that survive R14 are complete/recovered interfaces, `RuntimeAnnotations` keyed by
`BodyNodeId`, stable lowering lookup traits, one-shot facades over `CompilerSession`, retained normal and
no-prelude LSP sessions, synthetic package domains, and private mutation inside activation slots,
persistent builders/caches, cancellation state, and host resources.

guarantee, prohibitive cost, or user-owned HITL decision was found while decomposing the settled plan.
