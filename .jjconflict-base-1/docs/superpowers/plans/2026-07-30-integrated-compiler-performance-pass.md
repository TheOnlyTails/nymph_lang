# Integrated Compiler Performance Pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recover and exceed the pre-remediation latency of single-file and multi-module compilation without introducing a second compiler pipeline.

**Architecture:** First commit the independently discovered strict-link correctness fix, then establish durable cold and retained-session measurements. Use query events and sampling profiles to remove eagerly demanded shared work; add a single-module specialization only if a second A/B run proves graph/session overhead remains material after shared-query optimization.

**Tech Stack:** Rust nightly, Salsa 0.28, Criterion 0.7, cargo-nextest throughput profile, Linux `perf`, `/usr/bin/time`, `hyperfine`, Node 26, Jujutsu.

## Global Constraints

- Preserve exact `DefinitionId` and `RuntimeAssemblyPlacement` end to end.
- Preserve per-module Salsa caching and equal-output backdating.
- Preserve deterministic source, definition, assembly, and link order.
- Missing exact facts remain typed errors or explicit recovery, never guessed fallbacks or silent absence.
- Do not introduce compatibility flattening, dependency-body access, emitted-JS scanning, identity reconstruction, or a separate single-file compiler.
- Preserve the `|>` operator, nominal `==`/`!=`, and ordinary explicit `.equals()` dispatch.
- Run performance samples serially and uncontended; do not overlap them with builds or tests.
- Commit an optimization only when its gain exceeds measured variation and no measured workload regresses materially.
