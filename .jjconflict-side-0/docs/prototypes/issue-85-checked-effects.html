Checked effects contract prototype

A throwaway model for one question: can Nymph represent nominal effect sets, infer effect generics, enforce closed upper bounds, preserve narrower implementations, and delay iterator/task/resource effects without coupling them to ordinary type unification?

Prototype assumption

This page exercises a separate effect lattice. A row is a canonical set of nominal labels plus rigid effect parameters; call-site holes are solver variables with subset constraints. The solver chooses the least set satisfying all lower bounds, then checks every closed upper bound.

Expected failures are still Result values. Effects are static labels, not exceptions, handlers, or capabilities.

Decision options

A. Put effect variables into HM type unification

One solver, but equality-oriented unification fights the required subset relation and function-effect covariance. It also expands the blast radius of ordinary type inference.

Recommended B. Canonical rows + a separate subset solver

Keep value types and effect rows adjacent in callable/nominal signatures, but solve effects through join and subset constraints. Stable interfaces serialize only resolved labels and rigid parameters; inference variables never escape a body or call.

C. Collect concrete body effects after type checking

Cheap for first-order calls, but cannot infer !E through higher-order arguments, represent latent effects, or prove implementation narrowing. It would need replacement rather than extension.

Human decision frontier

The governing docs settle the language behavior. Issue 85 still needs confirmation of the checker contract:

  1. Representation: choose B, or accept the coupling/risk of A.
  2. Inference: infer each call-site effect variable as the least solution to subset constraints; reject only when that solution exceeds a closed upper bound.
  3. known + !_: preserve explicitly named effects as conservative API promises, then union inferred body effects; display the inferred remainder only diagnostically.
  4. Placement: store a row on every callable result and in effect-parameterized nominal arguments such as Task<T + !E>, Iterator<T + !E>, and Close<!E>; do not add special task/iterator/resource effect channels.
